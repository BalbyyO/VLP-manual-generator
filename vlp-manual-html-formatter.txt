Convert raw text, draft notes, or existing HTML snippets into standardized, light-and-dark-mode compatible HTML5 for VMware Lab Platform (VLP) manuals. Use when the user asks to format, standardize, or convert lab manual overviews, VM credentials, or step-by-step procedures into HTML for VLP.

Instructions
VLP Manual HTML Formatter
Convert raw instructional text, draft notes, or unstyled HTML into self-contained, theme-adaptive HTML5 snippets designed for the VMware Lab Platform (VLP) CKEditor (</> Source view).

When to Use
The user provides raw text, draft notes, or existing HTML for a lab manual and wants it converted or standardized into HTML5.
The user wants to format a course overview, instructional purpose section, VM credential callout, or numbered procedural steps for VLP.
The user asks to fix light mode or dark mode rendering issues (such as washed-out text, white table rows, or white code boxes) in VLP manual pages.
Workflow and Formatting Rules
1. Choose the Page Layout
Every output must be a self-contained snippet starting with a <style> block followed by the HTML container so it can be pasted directly into VLP's </> Source editor.

Course Overview / Introduction Pages: Use the .course-overview container when formatting front-page introductions, conceptual overviews, or standalone VM transition announcements.
Procedural Step Pages: Use the .lab-wrapper container with a .lab-header title bar and a .lab-table table when formatting numbered student exercises.
2. Preserve Step Text and Map Images Inline
Overview Polish: You may clean up and organize conceptual overviews so they read like an enterprise technical manual.
Strict Step Fidelity: Do not rewrite, combine, or alter the wording or sequence of numbered procedural steps. Keep the user's exact step instructions intact.
Inline Image Mapping: Place screenshots directly inside the table cell (<td>) of the step they correspond to, right below the instruction text, using .step-inline-img. Do not leave a stack of images at the bottom of the page. When the user provides one image per step, map them 1-to-1 in order.
Step Context Blocks: If a step includes "What you are doing" and "Why this matters" explanations, nest them inside <div class="step-context"> beneath the main action inside the same table cell.
3. Follow the Strict Red Box Rule
Reserve the translucent red callout box (.purpose-card or .lab-note) exclusively for two cases:

Instructional Purpose: Placed at the beginning of a manual (<h2>INSTRUCTIONAL PURPOSE</h2>).
Target VM Credentials: Placed only when first introducing a virtual machine or switching to a new target VM (<h2>Target VM Credentials</h2>). Omit the credentials box on subsequent pages that continue using the same VM.
4. Apply Semantic Inline Tags
UI Targets and Main Actions: Wrap buttons, icons, menus, window names, and VM names in <span class="ui-target"> (renders in bold high-contrast red).
Commands and Credentials: Wrap CLI commands, tools (such as gpedit.msc, whoami, sudo), usernames, and passwords in <code class="cmd-inline">.
Keyboard Keys: Wrap keystrokes (such as Enter or Windows Key + R) in <kbd class="key-press">.
Terminal Verification Output: Wrap expected command-line output in <div class="term-box"> and highlight the shell prompt with <span class="term-prompt">.

Gotchas
Never Use Opaque Light Backgrounds on Callout Cards: VLP forces light/white text in dark mode. Opaque light backgrounds (#fef2f2) make white text invisible. Always use translucent rgba(...) backgrounds with color: inherit !important;.
Strip VLP Table & List Backgrounds: VLP applies white backgrounds to odd table rows and black backgrounds to <ul> elements in dark mode. Always include background-color: transparent !important; on table elements and list items.
CKEditor Class Stripping on Images: VLP's rich-text editor sometimes strips classes from <img> tags when resizing. Always include .lab-table td img alongside .step-inline-img in the CSS so images inside table cells stay properly styled.
